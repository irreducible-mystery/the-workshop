# questions/ — the living workshop

*The eight-round record at the root of this repository is closed; there is no
round 9. But the project's own closing documents were careful to say what
stays open: "the door stays open … for whenever the pull returns" (PROOFS.md,
the completion question), and the floor's FINDINGS.md keeps a section titled
"What remains open." This directory is where that door leads.*

## How a question lives here

1. **Birth.** A question gets a row in [`OPEN-QUESTIONS.md`](OPEN-QUESTIONS.md)
   with a source (where the record names it) and a status. That row is the
   question's register entry — it exists before any work does.
2. **Charter.** If a question is taken up, it gets a directory —
   `q1-<short-name>/` — whose README states the question, the charter
   (what counts as an answer, what tools are allowed, what is out of scope),
   and the adjudicators (what checks its claims — the kernel, a bench,
   an instrument). Charter before benches; the old project's REGISTER.md
   discipline, inherited.
3. **Rounds.** Work proceeds however the new collaboration wants — but the
   sixteen norms (HANDOFF.md) are the default inheritance: no unmarked sorry,
   honest labels, anti-vacuity, negative controls, corrections loudest first,
   ledger-as-view, never write a count before the instrument renders it.
4. **Close.** A question closes on purpose, with a closing document and a git
   tag (`q1-close`), the way `round-8-close` marks the original. Closed
   questions move to CLOSED status in the ledger and stay in place — never
   deleted, per the house norm.

## What adjudicates this directory

Honestly: nothing yet, except its readers. `OPEN-QUESTIONS.md` is inventory
prose — the register the corrections law says is exactly where defects land.
Every row therefore carries a **source pointer** into the record, so any claim
about "what the record says stays open" can be checked against the record in
one hop. A row without a source is a proposal, and is labeled as one.
